# コードモード（シークバーにコードを表示）

v4.27.0で追加、v4.28.0で拡張。読み込んだ曲の和音を解析し、シークバーの波形の代わりにコード名のブロックを表示する。

## 使い方
- 設定帯(波形エリア下 / SPはMore内)の**View**で`Wave`→`Chord`(C Am7)→`Degree`(I vi7)を切替。Settings>Seek barにも同じ項目。
- Chord/Degreeにした時だけ解析が走る(波形モードのままなら何も計算しない)。解析中は波形を薄く出し、Viewに進捗%が出る。
- マーカー(線・番号・メモのラベル)・A/B・区間ハイライトは行のDOMなのでそのまま出る。**色**は波形と同じ規則(最後に通過したマーカーの色。再生済み=濃い、未再生=薄い。マーカー無しはアクセント色)。
- **候補表示**: ブロックの下段に、本命と差が小さい別候補を最大2つ(Settings>Chord candidatesでON/OFF。バーの高さに余裕がある時だけ)。
- **Keyと連動**: プレイヤーのKey操作(半音)に合わせてコード名(Chord)が移調して表示される。Degreeは変わらない。
- **Chord detail**(Settings): `Basic`=maj/min、`Extended`=+7/maj7/m7/dim/sus4(既定)、`Full`=+テンション(add9/6/m6/9/maj9/m9/m7b5/dim7/aug/sus2/7sus4/5)。
- **Chord key**(Settings): Auto(解析したキー)か手動(長調/短調12×2)。音名の#/♭表記・Degreeの基準・キーに合うコードの優先度に使う。曲を読み込むたびにAutoへ戻る(曲ごとの指定は保存)。
- **オンベース**(C/Eなど): ベース帯(〜260Hz)の最低音が構成音のどれかに強く出ていれば付く。根音のボーナスにも使う(Am7とC6のように構成音が同じコードを分ける)。

- スマホ幅では、View(Wave/Chord/Degree)とEditのスイッチはA/Bの左に並び、A/Bの右にクリック音と吸着(小節＋拍)のトグルが並ぶ(A/Bはアイコン(文字だけの丸ボタン)にして同じ段に収める。Viewは「‹ ›」ではなくタップで次の値へ進むボタン(`tap:true`)。EditはWaveのときだけ非表示(`hiddenWhen`)。極端に狭い幅/解析中の長い表示では末尾が次の段へ折り返す)。同じ要素を`syncMoreExtras`が移すだけなので設定帯・Settingsと値は同期したまま。PC幅は設定帯の中。

## 手動修正（Edit）
- 設定帯の**Edit**をON(Wave以外のとき)にして、コードのブロックをタップするとポップアップが開く(ONの間、行のタップはシーク/マーカー追加にならない。マーカーの線・A/B旗はそのまま操作できる)。
- 編集中の再生位置: 行の左の**時刻(数字)をタップ**=その行の頭へ移動(再生/停止はそのまま)。ポップアップの**Play from here**=タップした位置から再生。
- **ブロックの上下の余白**(ブロックは行の高さの14〜86%)をタップ=その位置へ再生位置を移動(ポップアップは開かない。再生/停止はそのまま)。
- **区間の長さ調整**: 区間の境目に乗せる(マウス)とつまみ(白い縦線)とカーソル(↔)が出て、左右へドラッグで境目が動く(0.05秒刻み・両隣は最短0.2秒まで)。ドラッグ中は時刻が出て、離すと保存。タッチは境目付近を横にドラッグ(境目には常時、小さなつまみ印が出る)。1回タップのつもりでドラッグ判定にならないよう、4px以上動いた時だけ動かす。ドラッグ中は指/ポインタの縦位置に一番近い行で時刻を決めるので、行をまたいで動かせる(上下端に近づくと自動でスクロール)。タッチでは境目をつかんでいる間は画面が縦スクロールしない。行末の境目は左の行の右端からも掴める。動かした両隣のブロックには点が付く。
- **拍に合わせた編集**(拍・小節の縦線が出ている時): 境目のドラッグは拍と裏拍(拍の真ん中)の一番近い所に吸着(Altを押している間は自由に0.05秒刻み)。Split hereも拍/裏拍に吸着。ポップアップの**Apply to whole bar**をONにすると、コードの変更(候補・Root・Type・Bass・No chord)がタップした小節ぜんぶに適用される(区間が小節より長ければ、その小節ぶんだけ分かれる)。**Split at bars**はその区間を小節線で分ける(コードはそのまま。あとから小節ごとに直す用)。
- ポップアップ: 候補チップ / Root / Type / Bass(タップで即反映)、No chord、Split here(タップした位置で2つに分ける)、Merge next(次の区間と1つに)、**Reset**(その区間を解析結果に戻す)、**Reset all**(曲全体)。
- 手動で直したブロックには左上に小さな点が付く。修正は「user」という上書きの層で持つので、Chord detail/Chord keyを変えて再解析しても消えない。

## 拍・小節の縦線(Grid)
- シークバーの背景(波形でもコードでも)に、小節の頭(やや濃い)と拍(薄い)の縦線を敷く。Settingsの**Grid**: Off / Bars / Bars + beats(既定)。解析はコードと同じ初回1回だけ(Gridがオフ以外なら、波形表示でも読み込み時に走る)。
- 計算は`QNChordCore.beats()`(10msのスペクトルフラックス→自己相関でテンポ→曲全体の櫛でテンポを0.02%刻みに精密化→DPで拍をたどる。120BPM未満で、半分の間隔の周期も同じくらい強い曲は倍(1拍=半分の長さ、上限240BPM)で取る)と`QNChordCore.bars()`(3拍子か4拍子かを判定。小節頭は低音のアタックとコードの切り替わり位置から選ぶ)。Workerがクロマの後に実行する。
- **小節頭の手動指定**: 再生位置を止めて、Settingsの**Bar start point → Set at playhead**(またはEditのポップアップの**Bar starts here**=タップした位置)。拍と拍の間でも指定できる。検出した拍の近く(拍間隔の12%以内)ならその拍が小節頭になり、離れていれば、検出した拍は使わず「その位置を起点に、検出テンポ(拍の最小二乗直線)で曲の端まで等間隔」の拍・小節線になる(テンポが大きく揺れる曲には向かない)。Clearで解除。曲ごとに保存(`bt`の4番目)。
- **小節頭の手動指定**: 再生位置を止めて、Settingsの**Bar start point → Set at playhead**(またはEditのポップアップの**Bar starts here**=タップした位置)。拍と拍の間でも指定できる。検出した拍の近く(拍間隔の12%以内)ならその拍が小節頭になり、離れていれば、検出した拍は使わず「その位置を起点に、検出テンポ(拍の最小二乗直線)で曲の端まで等間隔」の拍・小節線になる(テンポが大きく揺れる曲には向かない)。Clearで解除。曲ごとに保存(`bt`の4番目)。
- 手動補正(Settings): **Beats per bar**(自動/2〜7)、**Bar start**(小節の頭を拍単位で-3〜+3ずらす)、**Beat tempo**(Half/Auto/Double。倍・半分に取り違えた時用)。補正は曲ごとに保存(`bt`)。
- 編集モードの境目ドラッグは、拍の±0.08秒以内なら拍に吸着する。
- 合成音源での検証: テンポ誤差0.1BPM以内、拍位置の一致約99〜100%、ズレ±2ms、拍子判定(3/4)正解、小節頭の再現率100%(適合率約96%)。ドラムなし・スイングでも可。実際の曲(テンポ変化・ルバート・ブレイク)では外れうる。
- 保存: `qn_chords_<ファイル名>`に`beats`(拍時刻・低音アタック・BPM)と`bt`。次に開いた時は再解析しない。設定キーは`qn_grid`。

## コード切り替わりの拍合わせとシンコペ
- 解析したコードの境目を、検出した拍(と拍の真ん中=裏拍)に合わせる。Settingsの**Chord beat snap**(既定ON)。
- 境目ごとに候補(近くの拍・裏拍・動かさない)を比べる。点数は「そこで区切った時のコードの当てはまり」＋「そこで音が立ち上がっているか(拍/裏拍それぞれの普段より強い分だけ加点)」－「裏拍・グリッド外の罰」－「元の位置から遠い罰」(`qn-chord-core.js`の`snapSegs`、定数`SN_*`)。
- 裏拍に決まったコード(拍より半拍先に入る・遅れて入る)はシンコペとして`seg.sync`が立ち、ブロックの左下に小さな三角が付く。保存は`segs`の8番目の値と`snap`。
- 合成音源での検証: 境目のズレは平均約50ms→約3ms。裏拍で入るコード(半拍前のプッシュ)は11/11を検出、通常の曲での誤検出は0。実際の曲ではドラムやストラムが拍に乗らない/ブレイク/テンポ揺れで外れうる。外れた時はOffか、Edit(境目ドラッグ)で直す。
- ソフトなパッド系のようにアタックが無い曲では立ち上がりの手がかりが無く、裏拍検出は働きにくい(拍への吸着だけ効く)。

## 再解析
- Settingsの**Re-analyze chords**、またはEditのポップアップの**Re-analyze**で、その曲のコードと拍の解析をやり直す(保存済みの解析結果は捨てて波形から作り直す)。手動の修正(user)、キー・詳細度、拍の手動補正(拍子・小節頭・テンポ)は残る。波形は`player-chords.js`の`lastBuf`に保持している。

## 再解析
- Settingsの**Re-analyze chords**、またはEditのポップアップの**Re-analyze**で、その曲のコードと拍の解析をやり直す(保存済みの解析結果は捨てて波形から作り直す)。手動の修正(user)、キー・詳細度、拍の手動補正(拍子・小節頭・テンポ)は残る。波形は`player-chords.js`の`lastBuf`に保持している。

## 保存
- localStorage `qn_chords_<ファイル名>`: 解析結果(区間・候補・キー・詳細度)＋手動修正。次に開いた時は再解析せず即表示。曲の長さが0.6秒以上違えば別物として使わない。1曲400KBまで(通常は数KB)。
- Chord detail/Chord keyを保存時と違う設定にした時だけ、読み込み時の波形から再解析する(クロマの生データは保存しない)。
- 端末内のみ。Library同期・Backup/Importには含まれない(将来の課題)。曲を削除しても保存データは残る。

## 仕組み
- `player-ui-shared.js`の`decodeWaveform`が波形用にデコードした結果(8kHz前後)を`QNChords.offer(id, audioBuffer)`へ渡す(追加のデコードなし)。`loadFile`は`QNChords.reset()`で前の曲の解析を捨てる。
- `QNBars.setViewMode`→`QNChords.ensure()`→`qn-chord-worker.js`が`QNChordCore.chroma()`(STFT約0.5秒窓・hop約0.13秒→ピーク抽出→チューニング補正→12音クロマ＋ベース帯クロマ)。クロマは曲ごとに最大3曲ぶんメモリに保持。
- `QNChordCore.classify()`(テンプレート照合＋キー推定＋Viterbi平滑化＋オンベース＋候補)はメインスレッド。`QNChordCore.label()`が表示名(letter/degree/移調)を作る。
- 描画: `player-bars.js`の`paintChordRow`。ブロックは行の端で切れる側だけ角丸なし。幅に収まらないコード名はオンベースを省く→根音だけ→非表示。コード無し/無音は細い線。
- 修正UI: `player-chord-edit.js`(QNChordEdit)＋`style-chords.css`。タップ・ドラッグの奪い方と境目のつまみは`player-bars.js`末尾の編集モード用ハンドラ(`boundaryNear`/`QNChords.moveBoundary`)。つまみのDOM`.qn-chord-handle`は行の回収時に`stripRow`で除く。

## 精度と限界
- 4.36.0の精度改善: 拍のDPを等間隔寄りに(`B_TIGHT`=1000)・キック(低域)の重みを上げて拍の位相を安定。小節頭は「最初のコードの頭」で決めるのを、候補が9割以上拮抗した時だけに限定(実曲で半小節ずれていた)。コードの切り替えは粘りを強く(`SWITCH`=6)・拍の近くだけ乗り換えやすく。保存はv2(旧v1の拍/コード結果は捨てて再解析、手動編集と小節頭の指定は引き継ぐ)。
- 実曲(奇跡エレキB)での確認は「拍が等間隔で107bpm・小節頭がセクションの区切りと同じ位相」まで。コードの正解データは無いので、実曲でのコード一致率は未測定。
- 検証は合成音源のみ(ギター風の倍音＋ドラム/ノイズ＋単音メロディ)。通常のコード: 約97%一致。テンション/オンベース入りの曲: Fullで約92%一致(候補まで含めると約95%)。ルート(根音)だけなら約99%。実際の歌入り・厚いミックスの曲では下がる。
- 窓が長いので切り替わり位置は±0.25秒ほどずれうる。テンションは倍音と区別しにくいので、Fullは誤判定が増えうる(違和感があればExtendedへ)。
- キーチェンジ(転調)の自動検出はしていない(曲全体で1つのキー)。
- 端末負荷: 4分の曲でクロマ抽出は約1〜2秒(PC)。Workerが作れない環境ではメインスレッドで実行(固まる)。
- 4.37.0の拍の取り方: ①拍の探索上限を200→240BPM。②遅いテンポ(120BPM未満)は、半分の間隔の自己相関が元の7割以上なら倍で取る(`B_DBL_BELOW`/`B_DBL_RATIO`。実曲3曲で約107→215、102→204、108→216BPMになり耳で拍が合った。きれいな8ビートの合成曲は倍にならず従来通り)。③テンポの精密化(自己相関は10ms刻みで200秒に数秒ずれるため、曲全体の等間隔の櫛が立ち上がりに最も重なる間隔を±3%・0.02%刻みで探す)。保存はv3(v2以前の拍/コード結果は捨てて再解析。手動編集と小節頭の指定は引き継ぎ、倍/半・ずらしの設定は捨てる)。Nodeの検証用環境変数に`DBLBELOW`/`DBLRATIO`/`REFINE`を追加。
- Grid click(4.38.0〜): Settings>Grid clickをONにすると、再生中に小節頭=高い音・拍=低い音のクリックを縦線の位置で鳴らす(グリッドを耳で確認する用。ON/OFFのみ)。`player-grid-click.js`が鳴らす。ONにすると、Gridがオフでも解析が走る。保存キー`qn_grid_click`。
  - タイミング(4.38.1): `audio.currentTime`は約24ms刻みの階段状で、読んだ瞬間の値は最大1段古い。8msごとに(ctx.currentTime−audio.currentTime/rate)を測り、直近0.8秒の最小値=段差直後の値を「再生時計とAudioContextの対応」とする。再生開始・シーク・速度変更・一時停止のたびに取り直し(0.3秒は鳴らさない)、予約済みの未発音クリックは取り消す(古い位置のクリックが飛び出さない)。
  - 経路(4.38.1): クリックは曲と同じ経路の入口(SoundTouch→無ければ最初のEQ→無ければゲイン)へ入れる。SoundTouchを通さないと、その処理遅延(約160ms)ぶんクリックが曲より先に鳴る。実測(Chromium・SoundTouch入り)で曲とのずれは概ね±16ms以内(シークの直後の読み取りの24ms刻みのぶん)。

## 区切り位置を拍に沿わせる(v4.48.0)
- `classify()`のgridに`heads`(小節頭の時刻。player-chords.jsの`headTimes()`が`bars()`から作る。マーカーの小節頭指定も反映)を渡す。Viterbiの乗り換えコスト: 小節頭の近く=最も安い(`HEAD_MUL`)、ほかの拍=`BEAT_MUL`、裏拍=`SW_MID`、それ以外=`SW_OFF`。`snapSegs`の裏拍候補は`SN_OFF`(0.8)で、立ち上がりが強い時だけ採る(シンコペの例外)。
- 値の調整は node で環境変数(`HEAD_MUL`/`BEAT_MUL`/`SW_MID`/`SN_OFF`)から。4曲の実測: 区切りの約97%が拍上、68〜78%が小節頭、拍の裏は約3%。区間ごとの当てはまり(conf)の平均は下がらない。コード名の正誤は正解データが無く未測定。
- 保存済みの解析結果は古いまま残る。反映するには曲ごとに再解析(Chordsパネル)。
