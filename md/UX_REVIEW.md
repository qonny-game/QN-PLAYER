# UX見直し(操作性・美しさ・無駄な操作)のやり方 (UX_REVIEW.md)

「一度、操作性や美的観点、非効率な操作を見直してほしい」と言われた時の手順書。**やりたいこと(下の§1)を毎回ゼロから説明しなくていいように**、観点と進め方を固定した。
コード整理(`CLEANUP.md`)のメンテ時に**この見直しもやるかをユーザーに聞く**(§5)。

## 1. ユーザーのやりたいこと(固定の方針)
- 「使っている人が心地よい、製品らしい見た目と動き」。派手さより、迷わない・手数が少ない・見た目が揃っている。
- 提案は**気づいたことを全部**出す。どの部分でもよい(画面・操作・文言・動き・キーボード・SP/PC)。時間をかけてよい。
- 出した提案に優先度を付け、「やる」と言われたものは全部実装して、パッチで渡す(版は上げる)。
- アプリ内の文言は中立で簡潔・絵文字なし(チャットだけタメ口)。

## 2. 手順
1. **下ごしらえを1回で**: `python3 -I md/tools/ux_audit.py`(プロジェクトのルートで)。PC(1440)とSP(390)の全パネルを撮影し、はみ出し・小さいタップ領域・名前の無いボタン・下段バーが各幅(1280/1366/1440/1920)で収まるかを出す。画像は`_ux_audit/`(見終わったら消す)。
2. **画像を見る**: `main` → 各パネルの順。PCとSPを必ず両方。
3. **観点(§3)を1つずつ当てる**。気づきは「どこで・何が・なぜ困るか・案」の4点で1行にする。
4. **事実を確かめてから書く**: コードか計測で裏を取る。**推測で提案を書かない**(過去に「SPのA/Bが無い」と書いて、実は自分が前の版で壊していた、ということがあった=見つけ方としては良いが、原因の確認が先)。headlessで確認できないこと(実機の触り心地・音・GPU・iPhoneのマイク)は「未確認」と書く。
5. **優先度を付けて伝える**: 高=毎回の操作に影響/使えなくなる、中=迷う・見つけにくい、低=磨き込み。根拠(スクショ・数値)を添える。おすすめの進め方を1つ書く。
6. **実装**: 1つずつ直し、直したものは画面で再確認。仕様やキーを足したら guide / i18n / `QN_SHORTCUTS` / md も更新(`USER_DOCS.md`)。
7. `qa.py --quick` → `qa.py --ship 版 "一言"`。確認用のe2eは`md/tools/e2e_*.py`に足す(使い回す)。

## 3. 観点(チェックリスト)
**操作の手数・導線**
- よく使う操作(再生/停止、ループ、マーカー追加、速度、曲切替、A/B)が**1〜2タップ/1キー**で届くか。長押しや深い階層の奥に無いか。
- PCとSPで届き方が違いすぎないか(SPだけ手数が多い、など)。
- キーボードで練習の流れ(数秒戻る・A/B・速度)が完結するか。
- リセット・やり直し(ダブルタップ、Reset)の効き方が揃っているか。

**見えているか(発見しやすさ)**
- アイコンだけで意味が分かるか。ラベル/ツールチップがあるか。
- 現在の状態(今の行、ON/OFF、選択中)が一目で分かるか。トグルは**何のON/OFFか**書いてあるか。
- 狭い画面で**隠れて操作できない物**が無いか(横スクロールの奥など)。

**見た目の一貫性**
- 余白・文字サイズ・色・角丸・区切り線がパネル間で揃っているか。小さすぎる文字(10px未満)・薄すぎる文字が無いか。
- 同じ意味の部品が別の見た目になっていないか(スライダー、トグル、ボタン)。
- テーマ(ダーク/ライト/各アクセント色)で崩れないか。

**動き**
- 状態の変化に、短く自然な動き(100〜300ms、transform/opacityのみ)があるか。急に切り替わっていないか。
- 常時動くものが無いか(省電力。`power_check.py`)。`prefers-reduced-motion`で止まるか。

**タップ領域・アクセシビリティ**
- タップ領域が32px以上(SPは44px目安)。名前の無いボタンが無いか。`lang`、コントラスト、フォーカスの見え方。

**文言**
- 中立・簡潔・絵文字なし。日本語表示で英語が混ざっていないか(`i18n_check.py`)。

## 4. 過去の見直しで見つかった型(再発しやすいもの)
- 幅が足りない時に**横スクロール+スクロールバー非表示**で操作が画面外に隠れる(下段バー)。→ 折り返す(container query)か縮約する。
- **`:not()`などで詳細度を上げたCSS**が、別の場所の(後ろの)表示ルールに勝って、SP/PCの片方で消える。→ CSSは`@media`の中に閉じる。表示/非表示の変更後は**PC・SP両方**で確認する。
- フォーカスが残ったスライダーは「フォーカス中は値を同期しない」実装だと、プログラムからの値変更(リセット)が見た目に出ない。
- ラベルが選択中だけ見える設計は、初見に不親切。

## 5. コード整理の時に聞く(重要)
`md/CLEANUP.md` のお掃除・メンテを始める時、**最初にユーザーへ「UX見直し(操作性・見た目・無駄な操作の洗い出し)も一緒にやる?」と聞く**。
- やる → このファイルの手順で、お掃除の前(または後)に`ux_audit.py`から。提案をまとめて渡し、選んでもらってから実装する。お掃除(見た目を変えない)とUXの変更(見た目が変わる)は**別の版に分ける**。
- やらない → お掃除だけ進める。聞いたこと自体は不要なら省略(同じ作業で2度は聞かない)。
- 同じ文言のボタンが並ぶ（Track×2、Marker×3）と見分けにくい。方向は文字（`‹ Marker`/`Marker ›`、Prev/Next）でも示す。ラベルは48px幅（PC 1280）に収まる長さにする。
- トグルは「何のON/OFFか」と「OFFで何が起きるか」をラベルとtitleに書く（Speed/Keyの「Apply」＝OFFで原速・元のキー、設定値は保持）。
- 小さい部品のタップ領域は、見た目とレイアウトを変えずに広げる（スライダーは`height:32px; margin:-7px 0`、小ボタンは負のmargin、スイッチは`::before`で`inset`を外へ）。`ux_audit.py`は疑似要素の当たり判定を数えないので、スイッチ（42×26）は残って表示される。
