# QNPLAYER YouTube埋め込み プロトタイプ仕様（規約クリア版）

## 0. このドキュメントの目的

QNPLAYER（QNシリーズ）に追加予定の「YouTube URL再生機能」を、まず**単体の小さなプロトタイプ**として作る。
デザインは後回しで、簡易レイアウトでOK。動くことを最優先する。

**最終目標: YouTube規約に照らして健全なページを作り、将来的に広告収益を得る。**
そのため、規約的にグレーになり得る実装は最初から採用しない（第2章「規約遵守ルール」が最優先）。

## 1. 背景・前提（重要）

- QNPLAYERは「ブラウザ完結」のMP3プレイヤー。ローカルファイルは読み込み・保存できる。
- YouTubeについては、**音声の抽出・ダウンロード・保存は一切しない**方針。
- 使うのは **YouTube公式のIFrame Player API（埋め込みプレイヤー）のみ**。
- 保存するのは「URL・タイトル・マーカーの秒数」という**文字列/数値データだけ**（ブックマーク的な扱い）。
- そのため、波形表示・ピッチ変更（Web Audio API処理）はこのプロトタイプでは**対象外**。

## 2. 規約遵守ルール（最優先・破らない）

根拠: YouTube API Services Developer Policies（<https://developers.google.com/youtube/terms/developer-policies>）。
規約は更新されるため、公開・収益化の前に必ず原文を再確認すること。

### 2-1. 埋め込みプレイヤーには手を加えない

- 埋め込みは公式のIFrame Player APIで表示し、**YouTube標準のコントロールをそのまま表示する**（`controls: 0` は使わない）。
- プレイヤーの上にUIを**重ねない**（オーバーレイ、透明レイヤー、`pointer-events` での操作ブロックも禁止）。
- CSSでプレイヤーを**切り抜かない・隠さない・歪めない**（`overflow` での切り取り、`clip-path`、`opacity`、極小化、画面外配置など）。
- YouTubeのロゴ・リンク・帰属表示を隠さない、変更しない。
- プレイヤーは**常に画面内に表示する**。非表示にして音だけ流す（バックグラウンド再生）は禁止。
- プレイヤーのサイズは公式ドキュメントの推奨サイズ以上にする（実装時に公式のEmbedded Player要件で確認）。
- iframeを入れ子にしない（プレイヤーの直接埋め込みのみ）。

### 2-2. 自前UIは「埋め込みの外」に置く

- 自前シークバー・マーカーUIは、プレイヤーの**外側（下）**に、余白を空けて配置する。
- 自前UIから呼んでよいのは、**公式ドキュメントに載っているメソッドだけ**:
  `seekTo` / `getCurrentTime` / `getDuration` / `getPlayerState` / `setPlaybackRate`（将来）など。
- 非公式・未文書のAPIや、YouTubeページのDOM操作には**一切頼らない**。
- **再生 / 停止は標準コントロールを使う**。自前の再生・停止ボタンは付けない。
  （YouTube上の操作は、YouTube由来の操作だと利用者に明確に分かる形で、利用者自身が起動するのが望ましいため）
- 動画の再生開始は**必ず利用者の操作起点**にする。`autoplay` は無効（`0`）。
  マーカーのクリックによるジャンプは利用者操作なのでOK。

### 2-3. 音声・映像データに触れない

- 音声・映像のダウンロード、キャッシュ、保存、オフライン再生機能は**作らない**。
- 音声と映像の分離、Web Audio APIへの接続、`captureStream` 等による取り込みは**やらない**。
- YouTubeページや動画データの**スクレイピングはしない**。YouTube Data APIも今回は使わない。

### 2-4. 保存するデータを最小限にする

- 保存してよいもの: `videoId` / 入力されたURL / **利用者が自分で付けたタイトル** / マーカー（秒数・ラベル）。
- **YouTubeから自動取得したタイトル・サムネイル・再生数などは保存しない**（自動取得の`getVideoData().title`も保存に使わない）。
  規約上、YouTube由来のデータを長期保存できない。タイトルは常に利用者の手入力とする。
- 音声・映像・サムネイル画像のデータは保存しない。

### 2-5. 広告・課金の設計ルール（収益化を見据えて）

- **広告はプレイヤーの外に置く**。プレイヤーの上・中・直接隣接（重なる位置）に広告を配置しない。
- **「YouTubeのコンテンツしかないページ」にならないこと**。マーカー管理・リスト管理・（将来の）ローカルファイル再生など、
  YouTube以外の**独自機能が、それだけで価値になる**ページにする。
- ポップアップ、全画面インタースティシャル、誤クリックを誘う配置など、**邪魔な広告は使わない**。
- **YouTube動画の視聴そのものを有料にしない・条件付けしない**
  （課金は独自機能側のみ。例: マーカー保存数の拡張など。YouTube再生は常に無料）。
  ログイン要求など、YouTube以外の一般的な機能上の条件はOK。
- チャンネル登録・高評価・シェア等を**視聴の条件やポイント付与の対象にしない**。
- 広告ネットワーク（AdSense等）側の**独自審査基準（コンテンツの独自性など）も別途確認**する。
- **プロトタイプ段階では広告コードは入れない**。将来用に「広告枠エリア」だけレイアウト上で確保しておく程度でよい。

### 2-6. 著作権への配慮

- 権利者に無断でアップロードされた動画の利用を助長しない。
- 画面上に「権利者に無断でアップロードされた動画は使用しないでください」の旨の注意書きを置く。

### 2-7. 一般公開する時に必要になるもの（プロトタイプでは不要・メモ）

- 独自の利用規約に「YouTube利用規約（<https://www.youtube.com/t/terms>）への同意」を明記し、YouTube利用規約へのリンクを表示する。
- プライバシーポリシー（常時見える位置に表示）。含めるべき内容:
  YouTube API Servicesを利用していること / Googleプライバシーポリシー（<http://www.google.com/policies/privacy>）へのリンク /
  広告など第三者コンテンツの配信の開示 / Cookie・ローカルストレージ利用の開示。
- 埋め込む動画の「子ども向け」判定の扱い（子ども向け動画ではトラッキングを止める必要がある）。**公開前に調査して設計する**。
- HTTPSでの配信。
- 広告ネットワークの審査。

## 3. プロトタイプのスコープ

### やること

1. **URL入力 → 読み込み**
   - YouTube URLを入力して読み込む
   - 対応形式: `youtube.com/watch?v=xxxx` / `youtu.be/xxxx` / `youtube.com/shorts/xxxx` / `youtube.com/embed/xxxx`
   - 動画IDを取り出し、不正なURLならエラー表示
2. **リストに保存**
   - URLとタイトル（**利用者が手入力**）を保存
   - リストから選んで呼び出し、再生できる
   - 削除・タイトル編集もできると良い（最低限は追加と呼び出し）
3. **YouTube埋め込み表示**
   - IFrame Player APIで埋め込み表示、**標準コントロールそのまま**
   - 再生 / 停止 / 音量 / 全画面などは**YouTube標準コントロールで操作**する
4. **自前シークバー（埋め込みの外）**
   - 現在位置と全長を表示
   - ドラッグ/クリックで `seekTo()`
   - 埋め込みの標準シークバーと二重に存在してよい（自前側は「マーカー付き練習用シークバー」という位置づけ）
5. **マーカー**
   - 「現在位置にマーカー追加」ボタン（現在位置は `getCurrentTime()` で取得）
   - マーカーは `{ id, time(秒), label }`
   - 自前シークバー上にマーカー位置を表示
   - マーカーをクリック → その位置へジャンプ（`seekTo`）
   - マーカー位置の移動（**下記どちらか、または両方**）
     - 自前シークバー上でドラッグして位置調整
     - 「現在位置で上書き」ボタン
   - マーカーのラベル編集・削除
   - マーカーは動画ごとに保存し、同じ動画を開くと復元される

### やらないこと（今回は対象外）

- 音声データの取得・抽出・保存（**絶対にやらない**）
- 標準コントロールの非表示・置き換え、自前の再生/停止ボタン
- 波形表示、ピッチ変更、Web Audio APIへの接続
- ABループ（次のステップ。マーカー2つで実現予定）
- ローカルファイル再生との統合（別途、既存QNPLAYERに組み込む）
- 広告コードの設置、課金機能
- デザインの作り込み、SP最適化

## 4. データ構造（localStorage）

キー例: `qn_yt_items`

```json
[
  {
    "id": "item_001",
    "type": "youtube",
    "videoId": "xxxxxxxxxxx",
    "url": "https://www.youtube.com/watch?v=xxxxxxxxxxx",
    "title": "利用者が手入力したタイトル",
    "markers": [
      { "id": "m_001", "time": 83.5, "label": "サビ前" }
    ],
    "createdAt": 1790000000000
  }
]
```

- 音声・映像データ、YouTube由来のタイトル・サムネイルは一切含めない
- `type: "youtube"` は将来ローカルファイルと同じリストに並べるため

## 6. 技術方針

- **HTML / CSS / JS のみ**（ライブラリ不要）
- ファイル構成: `index.html` / `CSS/style.css` / `JS/app.js`
- YouTube IFrame Player API（`https://www.youtube.com/iframe_api`）を公式の方法で読み込む
- プレイヤー生成時の主なパラメータ: `controls: 1`（標準コントロール表示）、`autoplay: 0`
- 現在位置の表示は `setInterval`（200〜250ms程度）で `getCurrentTime()` をポーリング
- 全長は `getDuration()`、状態変化は `onStateChange` で検知
- シークバー操作中は、ポーリングによる表示更新を止める（ドラッグと競合しないように）

### 実装上の注意

- **`file://` で直接開くとIFrame埋め込みがエラーになることがある**。ローカルサーバー経由で確認すること（例: VS Code の Live Server、`npx serve`、`python -m http.server`）。
- 動画によっては埋め込み禁止のものがある。`onError` でエラーコードを拾い、「この動画は埋め込み再生できません」と表示する（回避策は作らない）。
- 第2章の規約遵守ルールに反する実装（オーバーレイ、プレイヤーの隠蔽、音声取得など）を、便利さのために追加しない。

## 7. 完成の目安（受け入れ条件）

### 機能

- [ ] YouTube URLを入力して埋め込み表示できる
- [ ] 不正なURLでエラーが出る
- [ ] タイトルを手入力してリストに保存でき、リロード後も残っている
- [ ] リストから選ぶと動画が読み込まれる
- [ ] 標準コントロールで再生・停止できる
- [ ] 自前シークバーが再生に合わせて動き、ドラッグで位置を変えられる
- [ ] マーカーを追加でき、自前シークバー上に表示される
- [ ] マーカーをクリックするとその位置へジャンプする
- [ ] マーカーの位置を移動できる
- [ ] 同じ動画を開き直すとマーカーが復元される

### 規約チェック（すべてチェックが付くこと）

- [ ] 標準コントロールが表示されている（`controls: 1`）
- [ ] プレイヤーの上に何も重なっていない
- [ ] プレイヤーがCSSで切り抜かれたり隠されたりしていない
- [ ] プレイヤーが常に画面に表示されている
- [ ] 自動再生していない（`autoplay: 0`）
- [ ] 自前の再生/停止ボタンがない
- [ ] 使用しているAPIメソッドが公式ドキュメントに載っているものだけ
- [ ] 保存データにYouTube由来のタイトル・サムネイル・音声・映像が含まれていない
- [ ] ダウンロード・保存・書き出しの機能が存在しない
- [ ] 注意書き（無断アップロード動画の不使用）が表示されている

## 8. 次のステップ（プロトタイプ後）

1. マーカー2つを使った **ABループ**（`seekTo` による区間ループ）
2. 再生速度変更（IFrame APIの `setPlaybackRate` で対応可能な範囲）
3. QNPLAYERのデザインシステム（配色トークン・フォント）への適用
4. ローカルファイルとYouTubeを同じリストに混在表示（種別アイコンで区別）
5. 公開準備（第2章2-7の項目: 規約・プライバシーポリシー・子ども向け判定・HTTPS）
6. 広告枠の設置（第2章2-5のルールに従う）
7. （別検討）ピッチ変更が必要な場合はChrome拡張機能化を検討。ただし個別に設計判断が必要

## 追補（2026-09-30 / QNPLAYER v2.20.0）：統合後に追加した機能と規約上の扱い

出典：YouTube API Services Required Minimum Functionality / Developer Policies（実装時に原文を確認）。

- **Auto Next（終了したらLibraryの次の動画を読み込む）**
  - 初期OFF。利用者が明示的にONにした時だけ動く（`localStorage: qn_yt_autonext`）。
  - 規約上、自動再生は「プレイヤーが画面に見えていて、その半分超が見えている」場合に限られる。
    そのため、①別タブ／②アプリ非表示／③プレイヤーが半分以上隠れている、
    のいずれかでは次へ進まない（`playerMostlyVisible()`）。
  - 同時に自動再生するプレイヤーは常に1つだけ（プレイヤー自体が1つ）。
- **再生スピード**：プレイヤーの**外**に置いた自前UI。倍率は`getAvailablePlaybackRates()`（YouTube標準と同じ）、
  変更は公式メソッド`setPlaybackRate()`のみ。プレイヤーの上には何も重ねない。
- **前/次マーカー**：`getCurrentTime()`→`seekTo()`のみ。
- **SP幅でパネルを開いてもプレイヤーは覆わない**：プレイヤーを画面上部に小さく残し（最低200×200px）、
  パネルはその下に表示する（v2.20.1〜）。アプリを閉じる時は`pauseVideo()`で一時停止
  （見えないまま再生され続けるバックグラウンド再生を作らないため）。
- **Library並べ替え**：自前データ（URL・手入力タイトル・マーカー）の順序のみ。YouTubeへは影響なし。
